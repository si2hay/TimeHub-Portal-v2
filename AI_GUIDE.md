## 🛑 ПРАВИЛО №2: ОТВЕТ ДОЛЖЕН БЫТЬ ПОЛНЫМ (БЕЗ ОГРЫЗКОВ)

- **ЗАПРЕЩЕНО** давать куски кода типа `// ... тут твой старый код ...` или `<!-- остальное без изменений -->`.
- Если вы меняете файл, вы пишете его **ЦЕЛИКОМ**, от первой строчки (комментария `/** @file ... */` или импортов) до последней скобки.
- Если пользователь просит дать 3 файла — вы даете 3 блока кода, каждый из которых является полным файлом.
- **Обязательно** указывайте полный путь к файлу перед блоком кода (например, `### src/features/timer.logic.js`).
- **В каждом файле должен быть заголовок** `@file` и `@description` (для JS) или `/** @file */` (для CSS), как показано в существующем коде.

- **`src/api/`** — только запросы к Supabase.

- **`styles/`** — разбиты на `base`, `layout`, `components`, `themes`. В `main.css` только `@import`.

## 1. Обзор проекта

**TimeHub-Portal v2** — учебный портал для студента. Переписан с нуля на Vite + Supabase.

### 1.1. Функционал
- **Многостраничное приложение (MPA)**: Главная (`app.html`), Вход (`index.html`), Админка (`admin.html`).
- **Выдвижное меню (Off-canvas)**: На главной странице при клике на логотип открывается меню профиля и настроек. Оно имеет два экрана (профиль и кастомизация) с плавной анимацией.
- **Авторизация и роли**: Регистрация/вход по Email через Supabase. Роли: `admin`, `sap`, `starosta`, `student`, `observer`.
- **Умный поиск (Smart Search)**: Игнорирует пробелы, дефисы и опечатки (использует расстояние Левенштейна). Внедрен в кастомные селекты и поиск пользователей.
- **Расписание**: Загружается из БД с учетом недели (чет/нечет) и дня.
- **Таймер пар**: Работает каждую секунду, учитывает звонки для 1-го и 2-го курсов, показывает прогресс-бар. Поддерживает **кастомное время**.
- **Замены**: Админ ставит замену на конкретную дату. Поддерживается **кастомное время**. Подсветка изменений красным.
- **Админ-панель**: 3 вкладки. Расписание (CRUD со сдвигом пар), Замены (CRUD со сдвигом и подсветкой), Пользователи.
- **Умная автоподстановка**: В админке при вводе предмета подставляются кабинеты и преподаватели.
- **Кастомизация**: Умный контраст, свои цвета, градиент, фоновые обои (URL), шрифты, размер текста, скругления, частицы на Canvas.
- **DANGER ZONE (Отладка)**: Скрытая панель для админов. Позволяет задать фейковое время/дату/день/неделю для тестирования сайта (с кастомным календарем).

### 1.2. Технологический стек
- **Сборщик:** Vite (v6.0.0).
- **Язык:** Vanilla JS (ES6 Modules).
- **Стили:** Чистый CSS (CSS-переменные, Grid, Flexbox).
- **Бэкенд:** Supabase (PostgreSQL, Auth, RLS).
- **Хостинг:** GitHub Pages.

### 1.3. Переменные окружения (`.env`)
В корне проекта лежит `.env` (не попадает в Git):
```env
VITE_SUPABASE_URL=твой_url
VITE_SUPABASE_ANON_KEY=твой_publishable_ключ
```

## 3. База данных (Supabase)

В проекте используются 3 таблицы (все с включенным RLS):

1. **`profiles`**: Связана с `auth.users`.
   - `id` (uuid), `email` (text), `role` (text), `group_name` (text), `settings` (jsonb).
2. **`schedules`**: Базовое расписание.
   - `id` (uuid), `group_name` (text), `week_num` (int), `day_num` (int), `pair_num` (int), `subject`, `room`, `teacher` (text).
   - `custom_start` (text), `custom_end` (text) — если заданы, таймер использует их вместо звонков.
3. **`substitutions`**: Замены.
   - `id` (uuid), `group_name` (text), `date_str` (date `YYYY-MM-DD`), `pair_num` (int), `subject`, `room`, `teacher` (text).
   - `custom_start` (text), `custom_end` (text).
   - *Если `subject` пустой — пара отменена.*

**RLS (Безопасность):**
- Читать `schedules` и `substitutions` могут все.
- Управлять могут только `admin` и `sap`.
- Читать/редактировать чужой `profiles` могут только `admin` и `sap` (через SQL-функцию `public.is_admin()`).

**🚨 ВАЖНО (Ошибки 403 и пустые массивы):**
Если данные не грузятся (пустой массив `[]`), это не всегда баг кода. Проверьте политики RLS в Supabase. Для записи (POST/DELETE) нужно выдать права ролям `admin` и `sap`:
```sql
CREATE POLICY "Admin full access schedules" ON schedules FOR ALL USING (
  auth.uid() IN (SELECT id FROM profiles WHERE role IN ('admin', 'sap'))
);
```
При запросах в Supabase всегда используйте `Number(weekNum)` и `Number(dayNum)`, а также `groupName.trim()`, чтобы избежать ошибок из-за строковых типов или пробелов.

## 4. Логика и математика

### 4.1. Время, Даты и Отладка
- **Неделя:** Разница дней от `26.10.2026` / 7 % 2 + 1.
- **День:** 1-5. В выходные возвращается 1.
- **Отладка:** Если в `localStorage` есть включенный `timehub_debug_state`, функции `getCurrentWeek`, `getCurrentDay` и `getNow` берут данные оттуда.

### 4.2. Кастомное время
- В админке (Расписание и Замены) можно задать `custom_start` и `custom_end` (формат `ЧЧ:ММ`).
- В `timer.logic.js` сначала проверяется кастомное время пары, и только если его нет — берется из звонков.

### 4.3. Звонки (Курсы)
- В `bells.logic.js` группы, начинающиеся на `26`, получают звонки 1-го курса. Все остальные (`25`, `24`, `23`) — звонки 2+ курса.

### 4.4. Замены и Расписание (Админка)
- В админке при смене номера пары срабатывает **логика сдвига**.
- Чтобы красная подсветка изменений работала, в `substitution.admin.js` делается **глубокая копия базового расписания** для сравнения.
- Функция `applySubstitutions` накладывает замены на базу.
- **КРИТИЧЕСКИЙ ФИКС ЗАМЕН:** На главной странице замены запрашиваются строго по дате `getDateForDayAndWeek(selectedDay, weekOffset)`.

### 4.5. Умный поиск (Smart Search)
- В `src/features/search.logic.js`.
- Очищает строку от спецсимволов и пробелов.
- Использует расстояние Левенштейна для поиска с опечатками.
- Внедрен в `createSearchableSelect` и поиск по пользователям в админке.

### 4.6. Настройки и Умный контраст
- Сохраняются в `profiles.settings` (JSONB).
- Применяются через `applyUserSettings()` в `settings.logic.js`.
- **Умный контраст:** Если фон карточек (surface) светлый, текст автоматически становится черным, если темный — белым.
- **Слои цветов:** `--surface-color` (карточки), `--glass-bg` (прозрачные панели), `--accent-color` и `--accent-hover`.
- **Темы:** `theme-glass` (по умолчанию, сильное размытие) и `theme-classic` (плотная темная). Классы вешаются на `body`.

### 4.7. Таймер и переключение недель
- Таймер всегда работает, даже если переключился на другой день.
- **НЕЛЬЗЯ** удалять таймер из DOM при переключении дня (он должен просто обновлять текст), иначе верстка прыгает.
- Переключение недель идет по кругу (0 - текущая, 1 - следующая, -1 - прошлая).

### 4.8. Стили и Анимации (Важно!)
- Убраны `transform: translateY()` при наведении (hover), чтобы элементы не «прыгали». Оставлена только подсветка фона и тени.
- Кнопки `.btn-primary` и активные вкладки используют `var(--accent-color)`. Никакого хардкода синего/зеленого (кроме `.btn-danger` и `.btn-success`).
- Карточки входа (`.auth-container`) используют стеклянный эффект с блюром.
